# Добавление туториалов

Инструкция для агента. Читать, когда пользователь просит добавить туториалы (обычно даёт ссылку на страницу темы в Notion). Правила ветвления и PR: раздел «Git workflow» в `AGENTS.md`. Вопросы с собеседований добавляются по другой инструкции: `docs/adding-questions.md`.

Работа рассчитана на сессию без контекста: всё нужное для переноса одной темы (страница темы Notion → разделы сайта) описано ниже.

## Как устроены туториалы на сайте

- Список тем и **нумерованных разделов** живёт в `src/lib/tutorials.ts` (поле `sections`). Страница темы `/tutorials/<topic>/` строится из него. Кнопка раздела получает ссылку автоматически, когда есть файл туториала с этой темой и номером раздела.
- Страница туториала — `src/content/tutorials/ru/<topic>/<slug>.md` (русский оригинал; `en/` — переводы), URL `/tutorials/<topic>/<slug>/`.
- Frontmatter: `title` (точно как раздел в `tutorials.ts`, но без номера) и `order` (номер раздела в теме, с 1). Связь кнопки со страницей идёт по паре «тема + `order`», не по названию.
- Картинки: `src/assets/tutorials/<topic>/<NN>-<name>.svg`, подключаются в Markdown относительным путём (`../../../../assets/tutorials/<topic>/...`), Astro сам учитывает `base` сайта.
- Стили врезок, `<details>`, таблиц и картинок — в `src/styles/global.css` (классы `.tutorial …`). Новых плагинов и компонентов для туториалов не нужно.
- Посмотри, что уже есть: `ls src/content/tutorials/ru` и `git log --oneline -15`. Темы без туториалов: проверь `tutorials.ts` (темы там есть, файлов нет) и спроси пользователя, если тема не названа.

## Процедура

1. **Подготовка.** `git fetch`, ветка от свежего `origin/main`: `git switch -c content/tutorials-<topic> origin/main`. Имя ветки не должно совпадать со старой веткой (проверь `git branch -a`). Один PR на тему.
2. **Состав темы.** Загрузи инструменты Notion через ToolSearch (`select:mcp__…__notion-fetch`, имя сервера возьми из списка deferred tools), открой страницу темы по ссылке пользователя: в `<content>` будут дочерние страницы «NN · Название». Сверь их число и порядок с `sections` в `src/lib/tutorials.ts`. Расхождение — спроси пользователя, не правь список молча.
3. **Slug-и.** Для каждого раздела придумай короткий kebab-case slug на латинице, уникальный в теме (`gcd`, `runloop`, `mrc-to-arc`). Составь карту `номер → slug` до написания файлов: она нужна для ссылок между разделами.
4. **Чтение страниц и картинки (самое хрупкое место).**
   - Читай страницы пачками по 3–5 параллельными вызовами `notion-fetch`.
   - Картинки в ответе — подписанные ссылки S3 вида `…/mNN-name.svg?X-Amz-…`. **Они живут 5 минут**: срок = `X-Amz-Date` + 300 с. Скачивай их **сразу после чтения пачки**, одним вызовом Bash с `curl -fsS -o <файл> '<url>'`, пока ссылки не протухли. Если ссылки истекли (curl вернул 403) — прочитай страницу заново и скачай по свежим.
   - Имя файла: `<NN>-<name>.svg`, где `NN` — номер раздела, `name` — имя из исходного файла без префикса `mNN-` (`m02-gcd-architecture.svg` → `02-gcd-architecture.svg`).
   - **Каждый SVG проверь**: `grep -ciE '<script|onload|onclick|href=|foreignObject' файл` должен дать 0. Иначе не коммить и сообщи пользователю.
   - Качай только картинки самих переносимых страниц. Просьба перенести туториалы — это согласие на скачивание этих картинок, на остальное оно не распространяется.
5. **Написание файлов.** Перенеси содержимое страницы в Markdown по правилам из раздела «Правила конвертации». Текст и код переноси дословно, не «улучшай» и не сокращай.
6. **Alt-тексты.** Alt берётся **дословно из `<desc>` самого SVG** (не придумывай и не достраивай обрезанное). Автоматически:

   ```python
   import re, glob, html
   img = re.compile(r'!\[(.*?)\]\((\.\./\.\./\.\./\.\./assets/tutorials/([a-z]+)/([^)]+\.svg))\)')
   for path in glob.glob('src/content/tutorials/ru/<topic>/*.md'):
       s = open(path, encoding='utf-8').read()
       def rep(m):
           alt, rel, topic, fn = m.groups()
           d = re.search(r'<desc>(.*?)</desc>', open(f'src/assets/tutorials/{topic}/{fn}', encoding='utf-8').read(), re.S)
           return f'![{html.unescape(" ".join(d.group(1).split())) if d else alt}]({rel})'
       open(path, 'w', encoding='utf-8').write(img.sub(rep, s))
   ```

7. **Отсылки между туториалами** (см. «Ссылки») — после того как написаны все файлы темы.
8. **Проверки** (все обязательны):
   - `npm run check` и `npm test` — без ошибок (`set -o pipefail; … 2>&1 | grep …`, вывод xcodebuild/swift к проекту не относится).
   - `npx astro build`, затем сверка с оригиналом: на каждой странице в `dist/tutorials/<topic>/<slug>/index.html` число `<details`, `<table`, `<img`, `astro-code` и `<h2` должно совпадать с тем, что было в Notion (подсчитай по исходнику). Расхождение = потерянный или сломанный блок.
   - Проверка ссылок: все относительные `href="../…"` в теле страниц (`class="prose tutorial`) должны вести на существующий `dist/…/index.html`. На странице темы число ссылок на `/tutorials/<topic>/…` должно равняться числу разделов.
   - Визуально: `mcp__Claude_Browser__preview_start` с конфигом из `.claude/launch.json` (создай локально, он не коммитится: `npx astro preview --port 4399`, порт 4321 обычно занят чужим `astro dev` — не убивай его). Открой страницу темы и 1–2 самые насыщенные страницы туториалов (таблицы, картинки, `<details>`), потом останови превью. Перед превью выполни `npx astro build`.
9. **PR.** Коммить только `src/` (не `.claude/`). Сообщение коммита и заголовок PR: `content: туториалы темы <Тема>`; тело PR — 2–3 предложения: что добавлено, где картинки, какие отсылки стали ссылками. Сразу `gh pr merge <n> --auto --squash`. Подробности — «Git workflow» в `AGENTS.md`.
10. **Отчёт пользователю** (по-русски, коротко): что добавлено и сколько, как проверено, что не проверялось (технические утверждения из Notion не перепроверялись), какие отсылки остались текстом, что делать дальше.

## Правила конвертации Notion → Markdown

Формат ответа `notion-fetch` — «enhanced Markdown». Правила (все выработаны на уже перенесённых темах, придерживайся их для единообразия):

- **Frontmatter**: `title` в двойных кавычках, `order` числом. Заголовок страницы Notion `NN · Название` → `title: "Название"`; эмодзи в начале заголовка выбрасываем.
- **Заголовки секций**: убрать эмодзи (`## 🍳 Аналогия: …` → `## Аналогия: …`). Блок `# Источники {toggle="true"}` → `## Источники` и обычный список. Разделители `---` между секциями убрать. H1 в теле не нужен (страница сама выводит `title`).
- **Callout** (`<callout …>`) → blockquote (`> …`). Для callout с несколькими абзацами или списком — пустая строка `>` между блоками. Цвета и иконки не переносим. «Что узнаешь» и «Нужно знать заранее» остаются blockquote-ами в начале страницы.
- **Определения** (`> **Термин** — …`) остаются blockquote-ами; две подряд идущие цитаты Notion разделяй `>` + пустая строка, иначе склеятся в один абзац.
- **Таблицы** `<table>` → pipe-таблицы. Пустая первая ячейка заголовка допустима. Цвета строк не переносим. Эмодзи ✅/❌ в ячейках → «да»/«нет». `|` внутри кода в ячейке экранируй или переформулируй.
- **`<details><summary>`** оставляем raw HTML. Внутри `<details>` вокруг Markdown-содержимого обязательны пустые строки (после `</summary>` и перед `</details>`), иначе Markdown не отрендерится. В `<summary>` Markdown **не работает**: обратные кавычки убери, `<`/`>` экранируй как `&lt;`/`&gt;`; эмодзи (`❓`) убери. Отступы-табы внутри `<details>` убери.
- **Колонки** `<columns>` → последовательные блоки с жирной подписью.
- **Блоки кода**: язык сохраняем (`swift`, `objective-c`), `plain text` → `text`, `c++` → `cpp`. Код внутри `<details>` — обычный fenced-блок с пустыми строками вокруг.
- **Форматирование Notion-артефакты**: `**текст ****`код`**` (разорванный жирный) склей в `**текст `код`**`; `<span color="blue">**(дополнено)**</span>` → `**(дополнено)**`; `\[ \]` → `[ ]`.
- **Картинки**: `![](…signed url…)` → `![<alt из <desc>>](../../../../assets/tutorials/<topic>/<NN>-<name>.svg)`.
- **Inline-код и ссылки** без изменений. Внешние ссылки в «Источниках» сохраняем как есть.
- Ничего не добавляй от себя: ни комментариев, ни «улучшенных» объяснений. Очевидную опечатку в тексте можно поправить, но упомяни об этом в отчёте.

## Ссылки между туториалами

- Относительные ссылки, без `base`: из `/tutorials/<topic>/<slug>/` на соседний раздел — `../<slug2>/`, на раздел другой темы — `../../<topic2>/<slug2>/`. Всегда с завершающим `/`.
- Ссылку делает текст отсылки: `тутор 03` → `[тутор 03](../init-inheritance-access/)`, `темы 01–03` → `темы [01](../a/)–[03](../c/)`, `тутор «GCD»` → `[тутор «GCD»](../../concurrency/gcd/)`.
- **Не ссылайся** на страницы, которых ещё нет: такая отсылка остаётся простым текстом. Когда появляется новая тема, пройдись по уже написанным темам (`grep -rn "тутор\|тем[аыуе] [0-9]" src/content/tutorials/ru`) и подключи ставшие возможными ссылки.
- Не ставь ссылки внутри блоков кода (комментарии), внутри заголовков и внутри `<summary>`.
- Не ссылайся на раздел самого себя.

## Типичные ловушки

- **Протухшие ссылки на картинки** — главная причина повторной работы. Не читай больше страниц, чем успеваешь скачать за 5 минут.
- **`git push` отвечает HTTP 400** при маленьком пуше: пересоздай коммит (`git reset --soft origin/main && git commit …`) и запушь снова; проверь, что GitHub-аутентификация в порядке (`gh auth status`).
- **Порт 4321 занят** чужим `astro dev`: не трогай его и не запускай Playwright e2e против него (в dev-режиме острова гидратируются иначе и e2e падают). Для e2e поднимай собранный `dist` на другом порту отдельным конфигом вне репозитория.
- **Старые ветки с похожими именами** (`feat/tutorial-pages` и т. п.) остаются локально: не переиспользуй их.
- **`.claude/`** — локальная папка (в ней `launch.json`, `skills/`), в коммит не попадает.
- Репозиторий публичный: не коммить id страниц Notion, подписанные ссылки, токены, локальные пути.
