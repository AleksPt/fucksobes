# FuckSobes MVP — дизайн

Дата: 2026-09-25

## Цель

Статический сайт для подготовки к iOS-собеседованиям: вопросы с собеседований и ответы на них в текстовом виде.

## Функционал MVP

1. **Главная** — сетка карточек-категорий (название, описание, число вопросов и сколько из них с ответом).
2. **Страница категории** — список всех вопросов категории. Ответ скрыт, раскрывается кликом (`<details>`). Вопросы без ответа тоже показываются, в раскрытом виде — «Ответа пока нет».
3. **Страница вопроса** — постоянная ссылка на отдельный вопрос с раскрытым ответом.
4. **Поиск** — в шапке на всех страницах, **только по формулировкам вопросов**; префиксный и нечёткий поиск, `ё = е`, горячая клавиша ⌘K / Ctrl+K, навигация стрелками.
5. **Анимации** — плавное раскрытие ответа (CSS), View Transitions между страницами, hover на карточках. Уважать `prefers-reduced-motion`.
6. Светлая/тёмная тема по системной настройке. Интерфейс только на русском.

Не входит в MVP: уровни сложности, аккаунты, прогресс, избранное, аналитика, тренажёр.

## Стек

- Astro 7 (статическая сборка) + TypeScript (strict).
- React 19 — только для интерактивных островов (поиск).
- Tailwind CSS 4 + `@tailwindcss/typography` для текста ответов.
- Shiki (встроен в Astro) — подсветка Swift, две темы: светлая/тёмная.
- MiniSearch — клиентский поиск по JSON-индексу, собранному при билде.
- Vitest — юнит-тесты; Playwright — один e2e smoke-тест.
- Хостинг: GitHub Pages, `https://alekspt.github.io/fucksobes/`, публичный репозиторий, деплой через GitHub Actions.

Правила для дешёвого переезда на Next.js в будущем: интерактив — только React-компоненты; логика — в `src/lib/*.ts` без зависимостей от Astro, где возможно; контент — чистый Markdown без MDX.

## Контент

- Источник правды — Markdown-файлы в репозитории: `src/content/questions/<id>.md`, один файл на вопрос.
- Frontmatter: `title` (строка), `category` (ссылка на категорию), `order` (целое, порядок внутри категории). Тело файла — ответ (пустое тело = ответа нет).
- Категории — `src/content/categories.yaml`: `id`, `title`, `description`, `order`.
- URL: `/<category>/` и `/<category>/<id>/`.

Категории (утверждены): Swift, Память, Многопоточность, UIKit, SwiftUI, Архитектура и паттерны, Алгоритмы и структуры данных, Сеть и хранение данных, Инструменты и сборка, Soft skills.

## Миграция из Notion (разовая)

Источник — одна страница Notion «Для тренировки»: 717 пронумерованных вопросов, у 374 есть ответ в toggle-блоке, категорий нет, много дублей.

Решения:
- Ответы переносятся **как есть** (только конвертация разметки Notion → Markdown), проверка и доработка — позже.
- Вопросы без ответа переносятся.
- **Дубли сливаются** в один вопрос; формулировка берётся из одного из исходных вопросов дословно; разные ответы дублей склеиваются через `---`, ничего не теряется.
- Категорию и дубли размечает агент (Claude) в `migration/mapping.json`, человек просматривает `migration/review.md`.
- После генерации Markdown-файлы становятся источником правды; повторный запуск генератора перезапишет ручные правки.
