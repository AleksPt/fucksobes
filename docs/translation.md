# Перевод контента на английский

Инструкция для агента. Читать, когда пользователь просит перевести вопросы или туториалы.

- Русский — оригинал: `src/content/questions/ru/<id>.md` → перевод `src/content/questions/en/<id>.md` (то же имя файла). Для туториалов — `src/content/tutorials/{ru,en}/<topic>/<id>.md`.
- Новая категория или раздел туториала: английские названия добавляются в `categories.yaml` (блок `en:`) и `src/lib/tutorials.en.ts`; без них сборка падает.
- Во frontmatter переводится только `title`; `category` и `order` копируются как есть.
- Перевод по смыслу, а не дословно: естественный английский уровня технической документации. Структуру (списки, абзацы, блоки кода, **жирный**) сохранять.
- Заголовки вопросов остаются вопросами в духе собеседования; вопросы от первого лица («Что будешь делать?») → «What would you do?».
- Код не менять; комментарии в коде и строковые литералы-примеры переводить. Идентификаторы, команды, флаги, имена API и файлов не трогать.
- Термины Apple и Swift оставлять оригинальными, русские кальки не переводить обратно по словарю: retain cycle, ARC, closure, trailing closure, protocol, extension, actor, main thread, run loop, view, view controller, delegate.
- Ссылки на другие туториалы (`../slug/`) копировать как есть: URL английской версии строятся так же.
- Каждая категория — отдельный PR (`content/en-<категория>`), заголовок `content: английский перевод категории «<Категория>»`.

## Туториалы и картинки

- Папки: `src/content/tutorials/{ru,en}/<topic>/<id>.md` (то же имя файла, `order` копируется, переводится `title` по английскому названию раздела из `src/lib/tutorials.en.ts`); картинки: русские SVG в `src/assets/tutorials/<topic>/`, английские в `src/assets/tutorials/en/<topic>/` (их не правят руками, они генерируются).
- Страница: структуру (заголовки, таблицы, `<details>`/`<summary>`, блоки кода, число ссылок и строк) сохранять один в один; не переводить термины Apple и идентификаторы; в коде переводятся только комментарии и строки-примеры; кириллицы в en не остаётся (в том числе в URL: кодировать процентами). Ссылки между туториалами (`../slug/`, `../../topic/slug/`) копировать как есть, внутрь блоков кода не добавлять. Текстовые «тутор 03» → "tutorial 03". Названия русскоязычных источников переводить с пометкой "(in Russian)".
- Картинка в странице: путь `../../../../assets/tutorials/en/<topic>/<NN>-<name>.svg`, alt = перевод `<desc>` этой картинки (тот же текст, что в словаре).
- Словарь `src/assets/tutorials/en/<topic>/translations.json`: `strings` (русская строка → английская, общие для темы; переиспользуй формулировки из словарей других тем), `files.<имя>.strings` (только для одного файла, в том числе перевод `<desc>`), `files.<имя>.edits` (литеральные правки раскладки). Формат подробно описан в docstring `scripts/svg-i18n/translate-svg.py`. Переводить нужно каждую кириллическую строку в `<text>`, `<title>` и `<desc>`; код и идентификаторы переводить не надо.
- Генерация (из корня; нужны `node_modules`): `python3 -m venv /private/tmp/fonttools-venv && /private/tmp/fonttools-venv/bin/pip install fonttools brotli`, затем `/private/tmp/fonttools-venv/bin/python scripts/svg-i18n/translate-svg.py <topic>`. Скрипт падает, если для строки нет перевода; повторный запуск даёт тот же результат.
- Проверка раскладки: `node scripts/svg-i18n/check-overflow.mjs <topic> --lang en` (должно вывести «Всё чисто»). Нашёл выход текста за блок, наложение или символ вне шрифта: сначала сократи или перефразируй перевод, и только если нельзя, поправь раскладку через `edits`. Ложные срабатывания сверяй с оригиналом: `--src`. Дополнительно открой 3–5 самых сложных картинок (ru и en рядом) глазами.
- При добавлении нового туториала в `ru/`: перевести страницу и картинки, проверить, что число ссылок и картинок в паре совпадает, и вернуть ссылки в уже переведённых страницах, если новый туториал стал целью отсылок. Проверки: `npm run check`, `npm test`, `npx astro build`, ссылки `href="../…"` ведут на существующие страницы в `dist`.
