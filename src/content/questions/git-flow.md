title: "Что такое Git Flow? Опишите основные принципы этого подхода"
category: git

---

Git Flow — модель ветвления с фиксированными ролями веток:

- `main` (или `master`) хранит только стабильный код релизов, каждый релиз помечается тегом;
- `develop` — основная ветка разработки, в которую сливаются готовые фичи;
- `feature/*` — ветки для отдельных задач, создаются от `develop` и в него же вливаются;
- `release/*` — подготовка релиза: исправление мелких багов и повышение версии, затем слияние в `main` и `develop`;
- `hotfix/*` — срочные исправления, создаются от `main` и вливаются в `main` и `develop`.

Плюсы: чёткий процесс для проектов с плановыми релизами (в том числе мобильных, где версию нельзя откатить у пользователей). Минусы: много долгоживущих веток, сложные слияния и медленная доставка изменений. Для непрерывной поставки часто выбирают более простые подходы, например trunk-based development или GitHub Flow.
