---
title: "Что такое Build Configuration?"
category: tooling
order: 43
---

**Build Configuration** (конфигурация сборки) — именованный набор значений build settings, используемый для сборки продукта таргета определённым образом. Xcode по умолчанию создаёт две конфигурации — **Debug** и **Release**, но их можно добавлять сколько угодно.

Типичный пример: конфигурации `Debug`, `Staging` и `Release` для одного и того же таргета — в каждой свой `API_BASE_URL`, свой уровень оптимизации компилятора и свой набор флагов условной компиляции (`#if DEBUG` / `#if STAGING`). При сборке выбирают нужную конфигурацию (через выбор схемы или параметр `-configuration` у `xcodebuild`), и Xcode подставляет соответствующий набор значений.

```
Настройка               Debug          Release
─────────────────────────────────────────────────
SWIFT_OPTIMIZATION_LEVEL  -Onone          -O
API_BASE_URL             dev.api.com    api.com
ENABLE_TESTABILITY        YES            NO
```

Конфигурации, как и build settings, удобно выносить в отдельные `.xcconfig`-файлы (`Debug.xcconfig`, `Release.xcconfig`) — это упрощает работу с `project.pbxproj`, версионирование и слияние изменений в команде.

Конфигурация — не то же самое, что **схема (Scheme)**: схема определяет, *что* и *как* запускать (какой таргет, тесты, какие аргументы окружения), а внутри себя для каждого действия (Run, Test, Archive) указывает, *какую* конфигурацию сборки использовать.
