> SOLID consists of five design principles that make code understandable, flexible, and easy to maintain.

- **S (Single Responsibility Principle)**: a module (class) should have only one reason to change.
- **O (Open/Closed Principle)**: a class is open for extension but closed for modification.
- **L (Liskov Substitution Principle)**: an object of a subtype can be substituted for an object of the base type without breaking the correctness of the program.
- **I (Interface Segregation Principle)**: by splitting an interface, the developer solves the problem of one fat interface.
- **D (Dependency Inversion Principle)**: high-level layers, such as a view controller, should not depend directly on low-level things, such as a networking component. Instead, they depend on an abstraction of that component.
