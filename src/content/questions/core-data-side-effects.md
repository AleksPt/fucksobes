---
title: "Какие возможны сайд-эффекты при работе с Core Data?"
category: data-storage
order: 28
---

Core Data удобен, но нарушение его правил использования легко приводит к неочевидным побочным эффектам.

- **Обращение к `NSManagedObject` не из своего контекста/потока** — краш или повреждение данных. Каждый `NSManagedObjectContext` привязан к своей очереди, и объекты нужно передавать между потоками только по `objectID`, а не напрямую.
- **`NSManagedObject` "протухает" (fault) после сохранения или мержа изменений** — обращение к его свойствам после этого либо подгружает данные заново из хранилища (лишний I/O), либо, если объект уже удалён, приводит к краху.
- **Утечки памяти из-за долгоживущего контекста** — `NSManagedObjectContext` кэширует все загруженные объекты; если не вызывать `reset()` или не давать контексту освобождаться, потребление памяти растёт.
- **Каскадное удаление по умолчанию** — если правило удаления (`Delete Rule`) для связи не задано явно, можно случайно удалить или обнулить связанные объекты, о которых не думали при написании кода.
- **Гонки при параллельном сохранении** — несколько контекстов, пишущих в один `NSPersistentStoreCoordinator` одновременно, могут привести к конфликтам слияния (`merge conflict`), если не настроена политика слияния (`mergePolicy`).
- **Побочные эффекты `save()`** — сохранение контекста синхронно проходит валидацию всех изменённых объектов; ошибка валидации одного объекта отменяет сохранение всего батча изменений.
- **Незаметный рост базы** — soft-delete через флаг вместо реального удаления, забытые временные объекты или неиспользуемые связи постепенно раздувают хранилище на диске.
- **Побочный эффект `NSFetchedResultsController`** — он держит сильную ссылку на делегата и активно уведомляет UI при любом изменении отслеживаемых объектов; забытая отписка или неправильно настроенные `sectionNameKeyPath`/предикаты приводят к лишним перерисовкам таблицы.

Большинство этих проблем снимаются дисциплиной: работать с контекстом только в его собственной очереди (`perform`/`performAndWait`), передавать объекты по `objectID`, явно задавать правила удаления и политику слияния, и не превращать один контекст в источник данных для всего приложения.
