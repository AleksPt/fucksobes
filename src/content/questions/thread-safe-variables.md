---
title: "Что такое thread-safe переменные? Потокобезопасно ли чтение и запись свойств класса?"
category: concurrency
order: 104
---

Переменная **thread-safe**, если к ней можно обращаться из нескольких потоков одновременно и результат остаётся корректным: нет data race, значение не портится и не читается «наполовину» записанным.

Свойства класса сами по себе **не потокобезопасны**:

- одновременные **чтения** безопасны, пока никто не пишет;
- **чтение + запись** или **запись + запись** из разных потоков — data race: можно прочитать устаревшее или испорченное значение, потерять обновление, упасть с крэшем (например, при изменении `Array` или `Dictionary`);
- `let`-константы и неизменяемые value-типы безопасны, потому что после инициализации не меняются.

Как сделать доступ безопасным:

- закрыть доступ **serial-очередью** (все чтения и записи идут через неё);
- **concurrent-очередь + barrier**: чтения параллельно, запись с `.barrier` эксклюзивно;
- **блокировки**: `NSLock`, `os_unfair_lock`, `NSRecursiveLock`;
- **atomic**-операции для простых значений (пакет Swift Atomics);
- **`actor`** — изоляция состояния на уровне языка.

```swift
final class Counter {
    private let queue = DispatchQueue(label: "counter.queue")
    private var _value = 0

    // Чтение и запись идут через одну serial-очередь
    var value: Int { queue.sync { _value } }

    func increment() {
        queue.sync { _value += 1 }
    }
}
```
