---
title: "Что означают IBOutlet и IBAction, для чего они нужны и что значат для препроцессора?"
category: uikit
order: 153
---

Оба — атрибуты для связи кода с Interface Builder (визуальным редактором storyboard и xib).

- **`@IBOutlet`** — помечает свойство как «розетку», в которую Interface Builder может подключить элемент интерфейса, нарисованный на холсте. После связывания система при загрузке view сама присваивает свойству ссылку на созданный элемент.

```swift
@IBOutlet weak var titleLabel: UILabel!
```

- **`@IBAction`** — помечает метод как обработчик действия, который можно привязать к событию элемента управления (нажатию кнопки, изменению значения слайдера) прямо в Interface Builder, перетащив связь от элемента к методу.

```swift
@IBAction func didTapButton(_ sender: UIButton) { ... }
```

Для самого языка и компилятора эти атрибуты **ничего не меняют** в поведении кода — с точки зрения рантайма это обычное свойство и обычный метод. Их единственная роль — быть **маркером для Interface Builder**: он статически анализирует исходный код, находит все `@IBOutlet`/`@IBAction` и на основе этого показывает в редакторе точки, которые можно соединить с элементами на холсте (кружки для перетаскивания связей). Исторически, ещё во времена Objective-C, `IBOutlet` и `IBAction` были просто пустыми макросами препроцессора (`#define IBOutlet` разворачивался в ничто) — они существовали исключительно для того, чтобы Interface Builder мог их найти при разборе исходников, а не для компилятора или рантайма.
