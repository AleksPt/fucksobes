---
title: "Каков цикл жизни UIView?"
category: uikit
order: 152
---

В отличие от `UIViewController`, у `UIView` нет единого фиксированного набора методов, гарантированно вызываемых по порядку, — но есть ключевые точки, через которые проходит любая view от создания до удаления.

1. **Инициализация.** `init(frame:)` — при создании кодом, или `init(coder:)` — при загрузке из xib/storyboard. Здесь настраивают то, что не зависит от финального размера view.
2. **Появление в иерархии.** `willMove(toSuperview:)` вызывается перед добавлением/удалением из родителя, `didMoveToSuperview()` — сразу после. Аналогично для окна: `willMove(toWindow:)` и `didMoveToWindow()` — здесь удобно, например, запускать или останавливать анимации в зависимости от того, видна ли view на экране.
3. **Раскладка (layout).** Когда размер или положение могут измениться, система (или вызов `setNeedsLayout()`) помечает view как нуждающуюся в раскладке, а затем вызывает `layoutSubviews()` — здесь вручную позиционируют сабвью, если не используется Auto Layout, либо переопределяют поведение поверх констрейнтов.
4. **Отрисовка.** `draw(_ rect: CGRect)` вызывается, когда view нужно отрисовать себя вручную через Core Graphics (переопределяют, только если делают кастомную отрисовку; для обычных view, полагающихся на слои и стандартные компоненты, метод не трогают). Перед этим можно вызвать `setNeedsDisplay()`, чтобы запросить перерисовку.
5. **Удаление.** `removeFromSuperview()` убирает view из иерархии и запускает `willMove(toSuperview: nil)`/`didMoveToSuperview()`. Если больше никто не держит сильную ссылку на view, она освобождается и вызывается `deinit`.

```swift
final class BadgeView: UIView {
    override func didMoveToSuperview() {
        super.didMoveToSuperview()
        // Удобное место узнать, что view добавили в иерархию
        startPulseAnimation()
    }

    override func layoutSubviews() {
        super.layoutSubviews()
        layer.cornerRadius = bounds.height / 2
    }
}
```

Ключевое отличие от жизненного цикла контроллера: у view нет отдельных «will/did appear» на экране пользователя — за это, если нужно, следит владеющий `UIViewController`, а сама view реагирует только на изменения иерархии, размера и необходимости перерисовки.
