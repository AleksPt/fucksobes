---
title: "Как происходит обработка UI-событий (нажатие, скроллинг) в RunLoop?"
category: uikit
order: 132
---

1. Касание обрабатывает система: событие от сенсора превращается в HID-событие и передаётся приложению через Mach-порт (источник событий run loop).
2. Главный run loop просыпается, получает событие через источник ввода и передаёт его `UIApplication`, который формирует `UIEvent` со списком касаний (`UITouch`) и вызывает `sendEvent(_:)`.
3. Окно (`UIWindow`) находит целевую view через `hitTest(_:with:)`, а событие идёт по responder chain: `touchesBegan`, `touchesMoved`, `touchesEnded`, а также жесты (`UIGestureRecognizer`) и действия `UIControl`.
4. Обработчики изменяют состояние, view помечаются как требующие раскладки или отрисовки, и в конце итерации run loop Core Animation выполняет layout и commit.

Во время скроллинга run loop переключается из режима `default` в `tracking`: приоритет отдаётся отрисовке и событиям касаний, а таймеры и другие источники, добавленные только в `default`, не срабатывают. Чтобы они работали и при прокрутке, их добавляют в режим `common`. Если обработчик события выполняется долго, run loop не может вовремя обновить экран.
