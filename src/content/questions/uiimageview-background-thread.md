---
title: "Есть UIImageView, в него нужно установить картинку. Можно ли это делать с бэкграунд-потока? Установится ли картинка?"
category: uikit
order: 154
---

Формально картинка **установится** — присваивание `imageView.image = someImage` с фонового потока не крашится и не игнорируется, свойство `image` обычное, никакой защиты от записи не с главного потока у него нет.

Но делать так **крайне нежелательно**. Вся отрисовка UI в UIKit должна происходить на главном потоке: как только новое значение `image` попадёт в очередь отрисовки, система должна перерисовать `UIImageView`, а рендеринг и работа со слоями (`CALayer`) не потокобезопасны. Установка картинки с фонового потока может привести к:

- визуальным артефактам или задержке обновления экрана (перерисовка может произойти не сразу, а с рассинхронизацией с остальным UI);
- гонкам данных, если в этот же момент с главного потока читаются или меняются свойства той же view;
- непредсказуемым крашам в дальнейшем — не обязательно в момент самого присваивания, а где-то ниже по стеку вызовов Core Animation, что усложняет отладку.

Правильный подход — загружать/декодировать изображение в фоне, а установку в `UIImageView` всегда переносить на главный поток:

```swift
DispatchQueue.global(qos: .userInitiated).async {
    let image = loadAndDecodeImage(from: url) // тяжёлая работа — в фоне

    DispatchQueue.main.async {
        imageView.image = image // а установка в UI — на главном потоке
    }
}
```

Это же правило касается любых других обращений к `UIView` и его подклассам — не только `UIImageView`.
