---
title: "Что такое структурированный и неструктурированный параллелизм?"
category: concurrency
order: 109
---

**Структурированный параллелизм** — время жизни задач ограничено областью видимости, где они созданы. Дочерние задачи (`async let`, `TaskGroup`) не могут пережить родителя: родитель дожидается их завершения. Из этого следует:

- **отмена** родителя автоматически отменяет детей;
- **ошибка** дочерней задачи попадает к родителю;
- **приоритет** и `task-local`-значения наследуются;
- утечек «забытых» задач нет, а код читается сверху вниз.

**Неструктурированный параллелизм** — задачи, у которых нет родителя, ждущего их завершения:

- `Task { }` создаёт новую задачу, которая наследует контекст актора и приоритет, но не привязана к области видимости;
- `Task.detached { }` не наследует ни контекст актора, ни приоритет.

За такими задачами нужно следить самому: хранить `Task` и вызывать `cancel()` в нужный момент, иначе они продолжат работать после ухода экрана.

Правило: по возможности использовать структурированные конструкции, а `Task { }` — для входа из синхронного кода (например, из обработчика нажатия).

```swift
// Структурированный: обе загрузки живут внутри функции
func loadScreen() async throws -> (User, [Post]) {
    async let user = api.loadUser()
    async let posts = api.loadPosts()
    return try await (user, posts)
}

// Неструктурированный: живёт сам по себе, отменять нужно вручную
let task = Task { try await loadScreen() }
```
