Это процесс оптимизации, который позволяет выбирать нужное поведение в зависимости от типа данных и их наследования.

это процесс определения, **какой код нужно выполнить в ответ на вызов метода или функции**. Основная цель диспетчеризации — выбрать правильную реализацию из нескольких возможных, исходя из контекста вызова. Она необходима для реализации полиморфизма, динамического поведения и других ключевых концепций программирования.

---

1. **Правильно определить реализацию метода** в зависимости от контекста (полиморфизм, протоколы, наследование).
2. **Соблюдать контракт интерфейса или протокола**.
3. **Обеспечить гибкость** при работе с абстракциями.
4. **Оптимизировать производительность** через выбор статической или динамической диспетчеризации.

определить, **какую конкретную реализацию метода вызвать**, исходя из контекста (например, типа объекта, который вызывает метод, или особенностей вызова). Она позволяет:

1.**Обеспечить правильный вызов метода при полиморфизме**:

- Если несколько типов (классы, структуры или протоколы) реализуют один и тот же метод, диспетчеризация определяет, какой именно метод использовать для конкретного типа.

2.**Реализовать динамическое поведение при наследовании и переопределении методов**:

- При наличии классовой иерархии диспетчеризация позволяет вызвать переопределённый метод в подклассе, даже если вызов делается через ссылку на базовый класс.

3.**Соблюдать контракт интерфейсов или протоколов**:

- Протоколы в Swift используют диспетчеризацию, чтобы обеспечить вызов метода у объекта, соответствующего протоколу, даже если реальный тип неизвестен на этапе компиляции.

---

> диспетчеризация метода — это то, как программа будет определять, какие инструменты использовать при вызове функции

- **`Direct Dispatch`**** (Статическая диспетчеризация)** — самый быстрый тип диспетчеризации. Адрес вызываемой функции определяется во время компиляции, поэтому затраты на такие вызовы минимальны. Для использования статической диспетчеризации вы можете пометить методы ключевым словом `private` или классы ключевым словом `final`.
- **`Table Dispatch`**** (Динамическая диспетчеризация)** — распространенный тип. Адрес вызываемой функции определяется во время выполнения. У каждого подкласса есть собственная таблица с указателем на функцию для каждого метода. По мере того как подклассы добавляют к классу новые методы, эти методы добавляются в конец этой таблицы. Затем к таблице обращаются во время выполнения, чтобы определить метод для выполнения. Это и есть динамическая диспетчеризация. В Swift данный подтип делится на два подтипа:
    - **`Virtual Table`** — используется при наследовании классов, что приносит дополнительные затраты.
    - **`Witness Table`** — используется для реализации протоколов, наследование отсутствует.
- **`Message Dispatch`**** (Отправка сообщений)** — самый долгий (по времени выполнения) тип диспетчеризации. Обеспечивает работу таких механизмов, как KVC/KVO или Core Data(?). Главная особенность этого типа —  у разработчиков появляется возможность изменять поведение отправки во время выполнения с помощью механизма swizzling.
