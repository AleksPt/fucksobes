---
title: "Как оптимизировать cornerRadius? Работает ли shouldRasterize для динамических view?"
category: uikit
order: 144
---

**cornerRadius.** Само свойство `layer.cornerRadius` дешёвое: скруглять фон и границу слоя можно без проблем. Проблема появляется при `layer.masksToBounds = true` (или `clipsToBounds`) для view с содержимым (подслои, изображения, много subview): для обрезки по скруглённой форме система рендерит слой вне экрана (offscreen rendering) и потом накладывает маску, что дорого при скролле, особенно в ячейках.

Как оптимизировать:

- не использовать `masksToBounds` без необходимости; для фона достаточно `cornerRadius` без обрезки содержимого;
- заранее скруглять изображения (при загрузке или кешировании) и показывать готовую картинку;
- рисовать скругление через `CAShapeLayer` или Core Graphics, использовать `cornerCurve` для «плавных» углов;
- накладывать поверх «уголки» непрозрачного цвета фона, чтобы визуально скруглить;
- проверять в симуляторе через **Color Off-screen Rendered**.

**shouldRasterize.** Свойство говорит слою закешировать своё отрисованное содержимое в bitmap и в следующих кадрах использовать его. Для статичных слоёв со сложной иерархией это ускоряет отрисовку. Для динамических view (содержимое или размер часто меняются, идёт анимация) кеш постоянно инвалидируется и перерисовывается: это дороже, чем без растеризации, и тратит память. Поэтому его включают только для статичного содержимого и задают `rasterizationScale = UIScreen.main.scale`.
