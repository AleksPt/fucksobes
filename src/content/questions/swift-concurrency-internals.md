---
title: "Как Swift Concurrency взаимодействует с GCD и OperationQueue под капотом?"
category: concurrency
order: 114
---

Swift Concurrency **не заменяет** GCD, а построена поверх него: планировщик задач (Task scheduler) компилируется на основе `libdispatch` — той же библиотеки, что стоит за GCD.

Как это устроено:

- для `@MainActor` используется **главная dispatch-очередь**: код на главном акторе выполняется на main queue, как и обычный GCD-код на `DispatchQueue.main`;
- задачи без привязки к конкретному актору исполняются на **глобальных конкурентных очередях**, в зависимости от приоритета — том же механизме, что лежит в основе `DispatchQueue.global(qos:)`;
- каждая созданная `Task` попадает в **executor**, связанный с кооперативным пулом потоков: в отличие от обычного GCD, число потоков этого пула ограничено числом ядер устройства — система не плодит потоки бесконтрольно.

Из этого следует важное практическое правило: **смешивать `DispatchQueue` внутри `Task` напрямую опасно**, потому что GCD ничего не знает о контексте `Task` (акторе, приоритете, отмене) и может «сломать» асинхронность:

```swift
Task {
    await doWork()
    DispatchQueue.main.async {
        self.label.text = "Done" // ❌ сбой архитектуры — смешали GCD и Concurrency
    }
}
```

Правильный вариант — оставаться в мире Swift Concurrency и переходить на главный актор через `await`, а не через GCD:

```swift
@MainActor
func updateUI() {
    self.label.text = "Done"
}

Task {
    await doWork()
    await updateUI() // ✅ корректный hop к MainActor
}
```

Когда это важно учитывать:

- при переходе со старого кода, где много `DispatchQueue.async`, на `async/await`;
- при тестировании — часть XCTest-колбэков всё ещё работает через GCD;
- при измерении производительности — `Task` может показаться «медленным», если конкурирует с GCD-очередями за общий пул потоков.

Best practice: в `async`-коде избегать `DispatchQueue` напрямую без явной необходимости (например, throttling или специфичный QoS) и использовать `MainActor.run { }`/`await`-переходы вместо `DispatchQueue.main.async`.
