---
title: "Как можно повлиять на диспетчеризацию?"
category: swift
order: 83
---

Классы по умолчанию используют динамическую диспетчеризацию: косвенный вызов через vtable. Повлиять на неё можно так:

- `final` у класса, метода или свойства запрещает переопределение, и компилятор может вызывать реализацию напрямую;
- `private` / `fileprivate` ограничивают видимость файлом; если в файле нет переопределений, компилятор сам выведет `final`;
- whole-module optimization позволяет вывести `final` для `internal`-объявлений, у которых нет переопределений в модуле;
- `dynamic` — наоборот, вызовы идут через отправку сообщений Objective-C, что медленнее прямого вызова.

```swift
final class C {
    var array: [Int] = []
    func doSomething() {}   // прямой вызов
}

class D {
    final var array1: [Int] = []  // прямой доступ
    var array2: [Int] = []        // через vtable
}
```

Для инлайнинга (подстановки тела функции в место вызова) есть атрибуты: `@inline(__always)` просит компилятор всегда подставлять тело (это сильная подсказка, но не абсолютная гарантия: например, рекурсивные функции подставить нельзя), `@inline(never)` запрещает инлайнинг, `@inlinable` открывает тело функции для оптимизации в других модулях. Без `final` и без известного точного типа компилятор не может подставить метод класса, поэтому `final`, `private` и whole-module optimization помогают и инлайнингу. Методы `dynamic` инлайнить нельзя.
