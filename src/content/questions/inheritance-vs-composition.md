---
title: "Чем наследование отличается от композиции?"
category: architecture
order: 48
---

**Наследование** — подкласс получает свойства и методы суперкласса и добавляет свои. Это отношение «является» (is-a): легковой автомобиль — это автомобиль. Связь жёсткая: подкласс зависит от реализации родителя, а иерархия задаётся на этапе проектирования.

**Композиция** — объект включает другие объекты как свои части и делегирует им работу. Это отношение «имеет» (has-a): у автомобиля есть двигатель.

```swift
class Engine { let power: Int; init(power: Int) { self.power = power } }

class Car {
    let engine: Engine
    init(engine: Engine) { self.engine = engine }
}
```

Композиция гибче: части можно заменять и комбинировать во время выполнения и через протоколы, объекты слабее связаны, нет хрупких иерархий и проблемы отсутствия множественного наследования. Поэтому принцип «предпочитайте композицию наследованию» (в Swift ему помогают протоколы и расширения).

Наследование уместно, когда подкласс действительно является подтипом родителя (принцип подстановки Лисков), они из одной предметной области, а код предка подходит наследнику и наследник в основном добавляет поведение. Так устроены иерархии UIKit (`UIViewController`, `UIView`).
