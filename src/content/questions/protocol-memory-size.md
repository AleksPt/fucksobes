---
title: "Как посчитать размер протокола в памяти (MemoryLayout)?"
category: memory
order: 61
---

Когда значение хранится с типом протокола (`any P`), Swift использует экзистенциальный контейнер, размер которого определяет `MemoryLayout<P>.size`. На 64-битной платформе:

- обычный протокол (`protocol P {}`): **40 байт** = буфер на 3 машинных слова для значения (24) + указатель на метатип (8) + указатель на protocol witness table (8);
- маркерный протокол вроде `Sendable`: **32 байта** — таблицы witness нет;
- `AnyObject`: **8 байт** — это class existential container, в нём только указатель на объект в куче;
- протокол, ограниченный классами, с методами (например, `Actor`): **16 байт** = указатель на объект (8) + указатель на witness table (8).

```swift
protocol P {}
print(MemoryLayout<P>.size)          // 40
print(MemoryLayout<AnyObject>.size)  // 8
```

Значения, которые помещаются в буфер из трёх слов, хранятся прямо в контейнере, а более крупные — в куче, а в буфере лежит указатель на них. Поэтому использование протокола как типа может приводить к аллокациям, а дженерики с ограничением (`<T: P>`) или `some P` этого избегают.
