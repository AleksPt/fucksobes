---
title: "Можно ли в конкурентной очереди сделать последовательное выполнение задач?"
category: concurrency
order: 105
---

Да, несколько способов, хотя по умолчанию конкурентная (`concurrent`) очередь выполняет задачи параллельно, не гарантируя порядок завершения.

- **`DispatchWorkItem` + `notify`/явные зависимости** — запускать следующую задачу только из завершающего блока предыдущей, вручную выстраивая цепочку.
- **`DispatchGroup`** с `wait()` или `notify(queue:)` — сгруппировать задачи и дождаться завершения каждой перед стартом следующей.
- **Barrier-задача** (`.barrier`) — гарантированно дожидается завершения всех ранее добавленных задач и не даёт стартовать следующим, пока сама не закончится, то есть на короткий момент превращает конкурентную очередь в последовательную. Подходит, если нужно один раз вклиниться с изолированной задачей (например, записью в общий ресурс), а не выстроить всю очередь последовательно.
- **Serial-очередь как `target`** — задать конкурентной очереди целевую (`target`) serial-очередь; тогда все задачи физически будут выполняться последовательно на потоке целевой очереди, хотя формально добавлены в конкурентную.
- Просто добавлять задачи **синхронно** (`sync` вместо `async`) одну за другой из одного потока — следующая задача добавится в очередь только после завершения текущей, что тоже даёт последовательность, но блокирует вызывающий поток.

```swift
let queue = DispatchQueue(label: "com.app.concurrent", attributes: .concurrent)
let group = DispatchGroup()

group.enter()
queue.async {
    performFirst()
    group.leave()
}

group.notify(queue: .main) {
    // Выполнится только после завершения первой задачи
    performSecond()
}
```

Если последовательность нужна для *всех* задач очереди постоянно, а не как исключение, проще и надёжнее сразу использовать **serial**-очередь — она для этого и предназначена.
