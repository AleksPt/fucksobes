---
title: "В чём разница между throws и rethrows в Swift?"
category: swift
order: 154
---

Оба ключевых слова помечают функцию как «выбрасывающую» ошибку, но с разным источником этой ошибки.

- **`throws`** — функция сама может выбросить ошибку в своём теле, независимо от того, принимает она параметры-замыкания или нет.
- **`rethrows`** — функция не выбрасывает ошибки сама, а лишь **пробрасывает** ошибку, которую выбросило переданное ей замыкание. Если ни одно из замыканий-параметров не помечено `throws`, вызов такой функции не нужно оборачивать в `try`.

```swift
func execute(_ operation: () throws -> Void) rethrows {
    try operation()
}

// Вызов без замыкания, которое может бросить ошибку — try не нужен
execute { print("ok") }

// Вызов с бросающим замыканием — try обязателен
try execute { throw MyError.failed }
```

Компилятор проверяет это на этапе компиляции: функция с `rethrows` обязана принимать хотя бы один параметр типа `throws`-замыкания, иначе объявление не скомпилируется.

Обработка ошибок в обоих случаях одинакова — через `do-catch`:

```swift
do {
    try execute { throw MyError.failed }
} catch {
    print("Поймали: \(error)")
}
```

`rethrows` часто встречается у функций высшего порядка стандартной библиотеки — например, у `map`, `filter`, `forEach` — чтобы не заставлять вызывающий код писать `try`, если переданное замыкание ошибок не бросает.
