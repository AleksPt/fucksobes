---
title: "Можно ли в качестве типа данных для @State использовать класс? Будет ли View перерисовываться при изменении свойств такого класса?"
category: swiftui
order: 46
---

Формально `@State` может хранить и класс — компилятор это не запретит. Но поведение будет не таким, как ожидается: `@State` отслеживает **само хранимое значение**, а для ссылочного типа значением является лишь ссылка (указатель) на объект.

Если у класса нет специальной поддержки наблюдения, изменение его свойств **не приводит** к перерисовке view: SwiftUI не видит мутации внутри объекта, ведь сама ссылка, хранящаяся в `@State`, не поменялась.

```swift
final class Counter {
    var value = 0
}

struct CounterView: View {
    @State private var counter = Counter()

    var body: some View {
        Button("\(counter.value)") {
            counter.value += 1 // мутация свойства — View НЕ перерисуется
        }
    }
}
```

Чтобы класс работал с `@State` и обновлял view при изменении свойств, его нужно сделать наблюдаемым:

- пометить макросом **`@Observable`** (iOS 17+, фреймворк Observation) — тогда SwiftUI автоматически отслеживает чтение каждого свойства в `body` и перерисовывает view при его изменении, а хранить такой объект можно прямо через `@State`;
- либо, в старом подходе, реализовать `ObservableObject` с `@Published`-свойствами и хранить объект через `@StateObject`, а не `@State`.
