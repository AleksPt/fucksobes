---
title: "Что такое Reuse Pool и как работает переиспользование ячеек под капотом?"
category: uikit
order: 157
---

**Reuse pool** — внутренний пул уже созданных, но сейчас не видимых на экране ячеек `UITableView`/`UICollectionView`, которые можно переиспользовать вместо создания новых.

Без переиспользования при скролле списка из тысяч строк пришлось бы аллоцировать тысячи `UITableViewCell` — это дорого по памяти и по времени на layout. Вместо этого при скролле:

1. Ячейка, ушедшая за пределы видимой области, не удаляется, а помещается в reuse pool (хранится по `reuseIdentifier`).
2. Когда снизу/сверху появляется новая строка, `dequeueReusableCell(withIdentifier:for:)` достаёт готовую ячейку из пула вместо `init`.
3. Для этой ячейки заново вызывается настройка контента (`cellForRowAt`), а старые данные предыдущей строки перезаписываются.

```swift
let cell = tableView.dequeueReusableCell(withIdentifier: "Cell", for: indexPath)
cell.textLabel?.text = items[indexPath.row]
return cell
```

**Важные следствия:**

- если не сбросить состояние ячейки (например, картинку или выделение) — оно «утечёт» на новую строку с другими данными;
- асинхронная загрузка данных для ячейки (картинки по сети) требует проверки, что ячейка не была переиспользована под другую строку к моменту завершения загрузки;
- `UICollectionView` и `UITableView` используют одинаковый механизм, но у `UICollectionView` есть ещё и reuse pool для supplementary views (заголовков/футеров).
