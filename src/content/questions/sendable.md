---
title: "Как использовать @Sendable и что гарантирует эта аннотация в async-контексте?"
category: concurrency
order: 116
---

**`@Sendable`** — аннотация, которая обозначает, что замыкание (или тип) можно безопасно передать между потоками, не нарушая memory safety. Это важно в асинхронном и параллельном коде: планировщик Swift может выполнять `@Sendable`-замыкания на других потоках, в том числе одновременно с другими задачами.

Swift Concurrency требует `@Sendable` у замыканий в ключевых точках API, где код реально может уйти на другой поток:

- `Task.init(priority:operation:)`;
- `Task.detached(priority:operation:)`;
- `TaskGroup.addTask { }`.

Если замыкание не помечено (неявно не выводится компилятором) как соответствующее `Sendable`, компилятор выдаёт warning или ошибку — в зависимости от режима строгой конкурентности (Swift 6).

```swift
func runInBackground() {
    Task.detached(priority: .background) { // @Sendable по требованию API
        print("Running...")
    }
}
```

Что гарантирует `@Sendable`:

1. **Копируемость/изоляция захвата** — замыкание не захватывает небезопасные ссылки на не-`Sendable` типы (например, обычный `class` без `@unchecked Sendable`).
2. **Иммутабельность захваченного** — все захваченные переменные внутри должны быть `let` (иначе — предупреждение или ошибка).
3. **Проверка компилятором** — компилятор статически проверяет, что всё захваченное соответствует `Sendable`, и не даёт случайно пронести гонку данных через границу потоков.

Если бы замыкание захватило, например, `self` типа `UIViewController` без соответствия `Sendable`, компилятор выдаст предупреждение — потому что `UIViewController` не потокобезопасен и обращаться к нему можно только с главного потока.

Как использовать безопасно:

- делать замыкания `@Sendable`-совместимыми там, где они передаются в `Task.detached`, `addTask`, `AsyncSequence.makeAsyncIterator()` и подобные API;
- избегать захвата `self` без `weak`/`unowned`, если тип не является потокобезопасным по своей природе;
- использовать `@unchecked Sendable`, только если вы вручную ручаетесь за потокобезопасность типа, которую компилятор не может проверить сам:

```swift
final class MyManager: @unchecked Sendable {
    // вы гарантируете потокобезопасность вручную,
    // например через внутреннюю блокировку
}
```
