**Facade** (фасад) — структурный паттерн, который скрывает сложность подсистемы за одним упрощённым интерфейсом.

Когда система разрастается, в ней появляется много классов, которые нужно правильно инициализировать в правильном порядке и заставить взаимодействовать друг с другом. Знать все эти детали каждому клиентскому коду неудобно и хрупко. Фасад берёт эту сложность на себя: он «знает», каким объектам подсистемы и в каком порядке передать запрос, а клиент обращается только к фасаду.

```swift
// Подсистема из нескольких классов с собственными деталями настройки
final class AudioDecoder { func prepare() { } }
final class VideoRenderer { func prepare() { } }
final class NetworkBuffer { func connect() { } }

// Фасад прячет их совместную настройку за одним простым методом
final class VideoPlayerFacade {
    private let audio = AudioDecoder()
    private let video = VideoRenderer()
    private let buffer = NetworkBuffer()

    func play(url: URL) {
        buffer.connect()
        audio.prepare()
        video.prepare()
        // ... запуск воспроизведения
    }
}

let player = VideoPlayerFacade()
player.play(url: someURL) // клиент не знает про Decoder/Renderer/Buffer
```

Когда применяют:

- нужно дать простой интерфейс к сложной подсистеме, которая усложняется по мере роста проекта;
- хотят разложить систему на слои и определить точки входа на каждый уровень, чтобы подсистемы общались только через фасады, а не напрямую.

Плюсы: изолирует клиентов от деталей сложной подсистемы, изменения внутри подсистемы не затрагивают клиентский код, если публичный интерфейс фасада остаётся прежним.

Минусы: фасад рискует превратиться в «божественный объект», знающий слишком много обо всех частях системы, — если он начинает разрастаться, стоит завести несколько более узких фасадов вместо одного.
