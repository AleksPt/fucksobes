---
title: "Как происходит выделение памяти в куче?"
category: memory
order: 75
---

В отличие от стека, куча — это область памяти, из которой можно запрашивать блоки **произвольного размера в произвольный момент времени**, и именно туда попадают значения, чей размер или время жизни неизвестны заранее: экземпляры классов, замыкания, которые захватывают состояние, а также value-типы с полями переменного размера.

Как это работает по шагам:

1. Когда нужно создать объект, runtime обращается к **аллокатору памяти** (`malloc` и его обёртки в рантайме Swift) и запрашивает блок нужного размера.
2. Аллокатор ищет подходящий свободный участок среди уже освобождённых блоков (по спискам свободной памяти, free list) или, если такого нет, расширяет управляемую область памяти у системы.
3. Найденный или выделенный блок помечается как занятый, и его адрес возвращается — на стеке остаётся только **указатель** на этот адрес в куче.
4. Когда объект больше не нужен (в Swift — когда счётчик ссылок ARC дошёл до нуля), память возвращается аллокатору через `free`, и блок снова становится доступен для переиспользования.

В отличие от стека, где освобождение — это просто сдвиг указателя, здесь аллокатору нужно **найти** подходящий блок и **учитывать фрагментацию**: если куча заполнена чередующимися занятыми и освобождёнными блоками разного размера, найти большой непрерывный участок сложнее и дороже. Поэтому:

- выделение и освобождение памяти в куче медленнее, чем на стеке;
- доступ к данным на стеке (через указатель на кучу) требует лишнего разыменования;
- куча — общая для всего процесса, а не для каждого потока отдельно, поэтому доступ к ней синхронизируется на уровне аллокатора, что тоже добавляет накладных расходов при многопоточном создании объектов.

```swift
final class Session {
    let id: UUID
    init(id: UUID) { self.id = id }
}

let session = Session(id: UUID())
// На стеке — только указатель `session`,
// сам объект Session выделен в куче через аллокатор
```
