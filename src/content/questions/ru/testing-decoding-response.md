---
title: "Как тестировать код, который декодирует ответ после сетевого запроса?"
category: testing
order: 23
---

Сетевой слой на реальный запрос не завязывают — тестируют отдельно шаг **декодирования**, изолировав его от сети.

**Подход:**

1. Держат в тестовом таргете JSON-фикстуру (файл `Response.json` в bundle тестов) или строку с ожидаемым ответом сервера.
2. Загружают её в `Data` и прогоняют через тот же `JSONDecoder`, что использует продакшен-код.
3. Проверяют, что результат смапился в ожидаемую модель.

```swift
func testDecodingUserResponse() throws {
    let data = try loadFixture(named: "user_response") // хелпер, читающий файл из test bundle
    let decoder = JSONDecoder()
    decoder.keyDecodingStrategy = .convertFromSnakeCase

    let user = try decoder.decode(User.self, from: data)

    XCTAssertEqual(user.id, 42)
    XCTAssertEqual(user.name, "Alex")
}
```

**Что стоит покрыть отдельными тестами:**

- успешный ответ с полным набором полей;
- ответ с отсутствующими опциональными полями — не должен падать;
- битый/неожиданный JSON — декодирование должно бросать ошибку, а не крашить приложение;
- нестандартные форматы (даты, snake_case ключи) — что стратегии `JSONDecoder` настроены верно.

Если декодирование встроено в сетевой сервис целиком (запрос + парсинг), сеть мокают через протокол-обёртку над `URLSession` (`URLProtocol`-стаб или собственный `NetworkClient`-протокол), а сам парсинг тестируют так же — отдельно на фикстурах, без реального запроса.
