**Proxy** (заместитель) — структурный паттерн, который подставляет вместо реального объекта объект-заменитель с тем же интерфейсом. Заместитель перехватывает вызовы к оригиналу и может выполнить что-то до или после передачи вызова настоящему объекту — либо не передавать его вовсе.

Структура: общий интерфейс сервиса, реализуют который и настоящий **сервис** (бизнес-логика), и **прокси** (хранит ссылку на сервис и решает, что сделать до/после делегирования вызова). Клиент работает через интерфейс сервиса и не отличает прокси от реального объекта.

```swift
protocol ImageLoading {
    func image() -> UIImage
}

final class RealImage: ImageLoading {
    private let url: URL
    init(url: URL) { self.url = url; loadFromDisk() } // тяжёлая загрузка сразу
    private func loadFromDisk() { /* ... */ }
    func image() -> UIImage { /* уже загруженное изображение */ fatalError() }
}

// Виртуальный прокси: откладывает создание тяжёлого объекта до первого обращения
final class LazyImageProxy: ImageLoading {
    private let url: URL
    private var real: RealImage?

    init(url: URL) { self.url = url }

    func image() -> UIImage {
        if real == nil { real = RealImage(url: url) } // создаём только при реальной необходимости
        return real!.image()
    }
}
```

Когда применяют:

- **виртуальный прокси** — отложить создание «тяжёлого» объекта до момента, когда он реально понадобится (ленивая инициализация);
- **защищающий прокси** — проверять права доступа перед тем, как пропустить вызов к сервису;
- **удалённый прокси** — представлять локально объект, который на самом деле находится на удалённом сервере, транслируя вызовы в сетевые запросы;
- **логирующий прокси** — вести историю обращений к сервисному объекту;
- **кеширующий прокси** («умная» ссылка) — кешировать результаты запросов и управлять их жизненным циклом, например считать ссылки на сервисный объект.

Плюсы: можно управлять жизненным циклом сервисного объекта незаметно для клиента, добавлять логику до/после вызова, не трогая сам сервис.

Минусы: усложняет код дополнительным слоем, а при неудачной реализации может заметно замедлить ответ сервиса.
