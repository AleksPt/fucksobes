---
title: "Что такое Relationship в Core Data?"
category: data-storage
order: 31
---

**Relationship** (связь) — свойство сущности, которое, в отличие от атрибута, хранит не значение, а **ссылку на другую запись** Core Data (или на запись той же сущности). Это аналог внешнего ключа в реляционной базе.

У связи задаются:

- **тип по количеству**: to-one (одна связанная запись) или to-many (набор записей, представленный `NSSet`/`Set` или, для упорядоченных связей, `NSOrderedSet`);
- **обратная связь (inverse)** — связь в противоположном направлении на другой сущности; Core Data настоятельно рекомендует всегда её задавать, чтобы граф объектов оставался согласованным при изменениях с любой стороны;
- **правило удаления (Delete Rule)** — что происходит со связанными объектами при удалении текущего: `Nullify` (обнулить ссылку), `Cascade` (удалить связанные объекты тоже), `Deny` (запретить удаление, пока есть связи), `No Action` (ничего не делать, рискует оставить «битые» ссылки).

Пример: сущности `User` и `Post`, у пользователя to-many связь `posts`, у поста to-one связь `author` с обратной связью на `posts`.

```swift
// Программный доступ к связи выглядит как обращение к обычному свойству
let post = Post(context: context)
post.author = user       // to-one
user.posts.insert(post)  // to-many, если задан inverse — Core Data сама
                          // синхронизирует post.author при вставке в user.posts
```
