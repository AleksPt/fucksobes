---
title: "Какие проблемы возможны, если после async/await запроса присваивать данные в переменную класса? Как их избежать?"
category: concurrency
order: 107
---

Код после `await` может продолжиться на **любом потоке** кооперативного пула, а несколько задач одного класса могут работать одновременно. Поэтому возможны проблемы:

- **data race**: две задачи одновременно пишут в свойство класса, а класс не изолирован. В Swift 6 (strict concurrency) компилятор выдаёт ошибку, в более ранних режимах — предупреждение;
- **обновление UI не с главного потока**, если свойство связано с интерфейсом;
- **порядок ответов**: результат старого запроса может прийти позже и перезаписать свежий;
- **reentrancy у actor**: между `await` состояние actor может измениться другой задачей, поэтому нельзя полагаться на значения, прочитанные до `await`.

Как избежать:

- изолировать класс или свойство: `@MainActor` для view model, отдельный `actor` для общего состояния;
- присваивать результат уже в изолированном контексте, а не из произвольной задачи;
- хранить `Task` и отменять предыдущий при новом запуске;
- после `await` перепроверять условия и не полагаться на прочитанное ранее состояние.

```swift
@MainActor
final class ProfileViewModel {
    private(set) var user: User?
    private var loadTask: Task<Void, Never>?

    func load() {
        loadTask?.cancel() // старый запрос не должен перезаписать новый
        loadTask = Task {
            guard let user = try? await api.loadUser(), !Task.isCancelled else { return }
            self.user = user // выполняется на главном акторе, гонки нет
        }
    }
}
```
