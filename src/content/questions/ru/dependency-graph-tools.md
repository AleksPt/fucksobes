---
title: "Расскажите об инструментах, которые помогают построить граф зависимостей проекта"
category: tooling
order: 51
---

- **`swift package show-dependencies`** — встроенная команда SPM. Выводит дерево зависимостей текущего пакета в виде текста, `JSON` (`--format json`) или формата `dot` (`--format dot`), который можно скормить Graphviz и получить визуальный граф. Показывает как прямые, так и транзитивные зависимости пакета.
- **Xcode → Project Navigator → Package Dependencies.** Для проектов, использующих SPM, Xcode показывает подключённые Swift-пакеты прямо в навигаторе проекта; раскрыв пакет, можно увидеть его содержимое. Это работает без сторонних инструментов, но не даёт ни визуального графа, ни дерева зависимостей, ни связей между собственными модулями приложения.
- **Tuist (`tuist graph`).** Инструмент для описания и генерации Xcode-проектов, у которого есть отдельная команда, строящая визуальный граф зависимостей между всеми таргетами и модулями проекта — с ним особенно удобно вылавливать неожиданные или лишние связи между модулями в модульных проектах.
- **`xcodebuild -list` и Build Timing Summary.** Это не инструменты построения графа: `-list` лишь перечисляет таргеты и схемы проекта, а Build Timing Summary показывает время сборки каждого таргета. Их используют вместе с графом зависимостей, чтобы понять, какие его узлы на практике самые дорогие.
- **Сторонние скрипты и линтеры границ модулей.** В крупных модульных проектах часто пишут собственные CI-проверки: они разбирают `Package.swift`/настройки таргетов и сверяют фактические зависимости с разрешёнными правилами (например, «модуль `Core` не должен зависеть от `Features`»), попутно строя граф для отчёта или визуализации.

Для менеджеров зависимостей уровня сторонних библиотек аналогичную роль играют lock-файлы: `Package.resolved` у SPM, `Podfile.lock` у CocoaPods и `Cartfile.resolved` у Carthage — по ним тоже можно восстановить полное дерево (включая транзитивные) зависимостей проекта на конкретный момент.
