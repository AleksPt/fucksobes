---
title: "В чём разница между .animation(_:value:) и withAnimation(_:_:)? Как выключить анимацию для сабвью, если для родительской View анимация включена?"
category: swiftui
order: 50
---

Оба способа задают анимацию для изменений состояния, но по-разному определяют, что именно анимировать.

- **`.animation(_:value:)`** — модификатор на конкретной view: анимирует **любое** изменение переданного значения `value`, влияющее на эту view и её потомков, независимо от того, где и как это значение поменялось. Привязан к месту в иерархии.
- **`withAnimation(_:_:)`** — императивная обёртка вокруг изменения состояния: анимирует **все** изменения UI, которые произошли внутри замыкания, независимо от того, к каким view они относятся. Привязан к моменту изменения, а не к конкретной view.

```swift
// .animation — анимирует только эту Text при изменении isExpanded
Text("Детали")
    .opacity(isExpanded ? 1 : 0)
    .animation(.easeInOut, value: isExpanded)

// withAnimation — анимирует все затронутые view сразу
withAnimation(.easeInOut) {
    isExpanded.toggle()
}
```

Чтобы **выключить** анимацию для конкретного сабвью, когда родитель анимируется через `withAnimation`, на этот сабвью навешивают `.animation(nil, value: ...)` (или, в новых версиях SwiftUI, `.transaction { $0.animation = nil }`):

```swift
VStack {
    HeaderView()          // анимируется вместе с родителем

    DetailView()
        .animation(nil, value: isExpanded) // выключена анимация только для этой view
}
.animation(.easeInOut, value: isExpanded)
```

`.animation(nil, value:)` перекрывает анимацию, унаследованную сверху, только для изменений, привязанных к конкретно этому `value`, — сама иерархия и корневая view продолжают анимироваться как задумано.
