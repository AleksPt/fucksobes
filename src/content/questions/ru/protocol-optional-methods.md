---
title: "Могут ли быть опциональные функции в протоколах?"
category: swift
order: 54
---

Да, но опциональные функции можно использовать только в **протоколах, помеченных `@objc`** (совместимых с Objective-C): механизм опциональных методов заимствован из Objective-C. Такие функции объявляются как `@objc optional`.

```swift
@objc protocol Delegate {
    @objc optional func didFinish()
}
// вызывать нужно с проверкой: delegate?.didFinish?()
```

Недостатки такого подхода: соответствовать протоколу могут только классы (структуры и перечисления не могут), а перед вызовом нужно проверять, реализован ли метод.

Чистая Swift-альтернатива — **реализация по умолчанию в расширении протокола**:

```swift
protocol Delegate { func didFinish() }

extension Delegate {
    func didFinish() {}   // тип может не реализовывать метод
}
```

Плюсы: работает для классов, структур и перечислений, поддерживает дженерики, а вызов не требует проверки, потому что реализация всегда есть. Минусы: не для всех методов есть универсальная реализация по умолчанию, и по вызову нельзя отличить реализацию по умолчанию от отсутствия собственной. Метод, объявленный в протоколе, вызывается динамически (witness table), а метод, добавленный только в расширение, диспетчеризуется статически.
