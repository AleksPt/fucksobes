---
title: "Что произойдёт, если вызвать setNeedsLayout() внутри layoutSubviews()?"
category: uikit
order: 101
---

`setNeedsLayout()` помечает раскладку view как устаревшую, и на ближайшем проходе цикла обработки событий `layoutSubviews()` будет вызван снова. Если сделать это внутри самого `layoutSubviews()`, view будет постоянно запрашивать повторную раскладку: получится цикл, который расходует процессор и может подвесить интерфейс.

```swift
override func layoutSubviews() {
    super.layoutSubviews()
    setNeedsLayout()      // так делать нельзя: раскладка будет запрашиваться бесконечно
}
```

Цикл возникает и косвенно: например, внутри `layoutSubviews()` меняется размер или текст подвью, а это снова делает раскладку недействительной. Для констрейнтов у UIKit есть защита: если обновление ограничений не стабилизируется, выбрасывается исключение о том, что окно слишком много раз запрашивало обновление. Для ручной раскладки такой защиты нет, поэтому внутри `layoutSubviews()` нужно только расставлять подвью и не менять то, что инициирует новую раскладку.
