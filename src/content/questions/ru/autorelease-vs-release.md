---
title: "В чём разница между autorelease и release?"
category: memory
order: 77
---

Оба сообщения уменьшают счётчик ссылок объекта, но в разный момент времени.

- **`release`** уменьшает retain count **немедленно**. Если счётчик доходит до нуля, объект уничтожается сразу же.
- **`autorelease`** не уменьшает счётчик сразу, а лишь ставит объект в очередь текущего `NSAutoreleasePool` (`@autoreleasepool` в Swift). Фактический `release` объекту отправится **позже**, когда пул будет очищен (обычно в конце текущего цикла run loop).

```objc
NSObject *obj = [[NSObject alloc] init]; // retain count 1
[obj release];                            // retain count 0 сразу — объект уничтожен

NSObject *other = [[[NSObject alloc] init] autorelease]; // retain count 1
// объект жив здесь и ещё какое-то время после,
// пока не очистится авторелиз-пул
```

`autorelease` нужен, когда объект должен «пережить» текущую область видимости и вернуться из метода как результат, но при этом вызывающий код не обязан явно им владеть: классический пример из Objective-C — фабричные методы вроде `[NSString stringWithFormat:]`, которые отдают автоосвобождаемый объект, а не требуют от вызывающего кода вручную звать `release`.

В Swift с ARC оба сообщения компилятор расставляет автоматически, а сам `@autoreleasepool` в объектах Foundation обычно нужен только для управления пиковой памятью в длинных циклах, создающих много временных объектов Objective-C.
