---
title: "Что такое APNs и как он работает?"
category: networking
order: 18
---

**APNs** (Apple Push Notification service) — сервис Apple, который доставляет push-уведомления от серверов разработчиков на устройства пользователей через постоянное защищённое соединение с системой, не требуя, чтобы приложение было запущено.

Как это работает по шагам:

1. Приложение вызывает `UIApplication.shared.registerForRemoteNotifications()`.
2. Система устанавливает защищённое соединение с APNs и получает уникальный **device token** — адрес, по которому APNs может найти конкретное устройство и приложение.
3. Токен приходит в делегат `application(_:didRegisterForRemoteNotificationsWithDeviceToken:)`, приложение отправляет его на свой backend-сервер и сохраняет там.
4. Когда серверу нужно отправить уведомление, он формирует запрос (payload в формате JSON) и отправляет его в APNs — по HTTP/2 через **APNs Provider API**, авторизуясь либо сертификатом, либо JWT-токеном на основе ключа подписи (`.p8`).
5. APNs находит устройство по device token и доставляет уведомление через постоянное соединение, даже если приложение не запущено или устройство спит.
6. Система показывает уведомление (баннер, звук, бейдж) согласно payload, либо, если задан `content-available: 1`, будит приложение в фоне для silent push.

```json
{
  "aps": {
    "alert": { "title": "Новое сообщение", "body": "У вас непрочитанное сообщение" },
    "sound": "default",
    "badge": 1
  }
}
```

Важные детали:

- device token может измениться (переустановка, восстановление из бэкапа, смена устройства) — приложение должно обновлять его на сервере при каждом запуске;
- за обработку самого уведомления на устройстве и его отображение отвечает `UNUserNotificationCenter`;
- для тестирования есть **sandbox**-окружение APNs, отдельное от production.
