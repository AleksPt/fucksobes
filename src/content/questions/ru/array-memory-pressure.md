---
title: "Что происходит с памятью, если заполнять массив огромным числом элементов? Есть ли разница между reference и value type?"
category: memory
order: 72
---

Массив в Swift хранит элементы в одном непрерывном буфере в куче. При нехватке ёмкости буфер растёт: выделяется новый, примерно вдвое больше, элементы переносятся, старый освобождается. Поэтому в момент роста одновременно нужна память под старый и новый буфер, и для очень больших массивов это может стать пиковой нагрузкой. Если известен размер, заранее вызывают `reserveCapacity(_:)`.

**Массив reference type (классы).** В буфере лежат только указатели (по 8 байт), а сами объекты выделяются отдельно в куче, у каждого есть заголовок (метаданные и счётчик ссылок, 16 байт). Итого на элемент уходит больше памяти, объекты разбросаны по куче (хуже локальность кеша, фрагментация), а каждый `malloc` и работа с refcount замедляют выполнение. При копировании массива копируются лишь указатели (copy-on-write), объекты общие.

**Массив value type (структуры).** Элементы лежат прямо в буфере, без заголовков и отдельных выделений. Память плотнее и быстрее, но один непрерывный блок памяти должен найтись целиком, а при росте копируется весь его объём, а не указатели. Если у структуры есть внутренние ссылки (строки, массивы), их данные всё равно в куче.

**Когда память заканчивается.** iOS не использует swap: система шлёт предупреждение (`didReceiveMemoryWarning`, `UIApplication.didReceiveMemoryWarningNotification`), а если приложение продолжает расти, завершает его (jetsam, Out of Memory) без вызова `applicationWillTerminate`. Что делать: не держать всё в памяти (пагинация, подгрузка по требованию), освобождать кеши по предупреждению, использовать компактные value-типы и обрабатывать данные пачками.
