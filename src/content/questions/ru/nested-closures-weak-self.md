---
title: "Если есть несколько вложенных замыканий, обязательно ли писать [weak self] в каждом?"
category: memory
order: 72
---

Нет, не обязательно. `[weak self]` нужен там, где замыкание создаёт **цикл сильных ссылок**: `self` хранит замыкание (прямо или через цепочку объектов), а замыкание строго захватывает `self`. Если цикла нет, слабая ссылка не нужна.

Как быть с вложенностью:

- Достаточно поставить `[weak self]` во **внешнем** замыкании. Внутреннее замыкание захватит уже слабую (опциональную) переменную `self`, а не сильную ссылку.
- Если во внешнем замыкании сделать `guard let self`, внутреннее будет захватывать `self` строго. Это безопасно, пока внутреннее замыкание недолговечное и не сохраняется в `self`: сильная ссылка живёт только до его завершения.
- Для **non-escaping** замыканий (`map`, `filter`, `forEach`, `sync`) слабый захват не нужен: они выполняются сразу и не хранятся.
- Если внутреннее замыкание тоже сохраняется (например, в свойстве `self` или в долгоживущем объекте), там нужен отдельный `[weak self]`.

```swift
func load() {
    // Внешнее замыкание: слабый захват разрывает цикл
    service.fetch { [weak self] result in
        guard let self else { return }

        // Внутреннее замыкание выполняется сразу и не сохраняется,
        // поэтому дополнительный [weak self] не нужен
        let items = result.map { self.convert($0) }

        // Замыкание уходит в другую очередь и живёт недолго:
        // после выполнения сильная ссылка освободится
        DispatchQueue.main.async {
            self.items = items
        }
    }
}
```
