---
title: "Сколько потоков могут иметь serial и concurrent очереди?"
category: concurrency
order: 103
---

**Serial-очередь** в каждый момент времени использует не больше одного потока: блоки выполняются строго по одному, следующий стартует после завершения предыдущего. При этом поток не закреплён за очередью: разные блоки одной serial-очереди могут исполняться на разных потоках пула. Исключение — `DispatchQueue.main`, она всегда работает на главном потоке.

**Concurrent-очередь** может выполнять несколько блоков одновременно, то есть использовать несколько потоков. Жёсткого лимита в API нет: число потоков определяет GCD, исходя из количества ядер, нагрузки и того, заблокированы ли уже выданные потоки.

- Реальный параллелизм ограничен числом ядер: потоков может быть больше, но одновременно исполняться будет не больше, чем ядер.
- Если потоки блокируются (`sync`, семафоры, `sleep`), GCD создаёт новые, чтобы очередь не встала. Так возникает **thread explosion**, а у системы есть предел на число потоков.
- Несколько serial-очередей вместе тоже могут занимать несколько потоков: каждая по одному, но параллельно друг другу.

```swift
let serial = DispatchQueue(label: "serial")
let concurrent = DispatchQueue(label: "concurrent", attributes: .concurrent)

// В serial-очереди блоки идут по одному
serial.async { print("A") }
serial.async { print("B") } // стартует только после A

// В concurrent-очереди блоки могут идти одновременно на разных потоках
concurrent.async { print("C") }
concurrent.async { print("D") }
```
