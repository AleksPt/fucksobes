---
title: "Какие особенности стоит учитывать при использовании @MainActor и как избежать «чрезмерной сериализации»?"
category: concurrency
order: 120
---

`@MainActor` гарантирует, что помеченный метод, свойство или весь тип будет выполняться на главной очереди (main thread), а Swift автоматически делает hop к `MainActor`, если вызов происходит вне его контекста. Обычно им помечают всё, что обновляет UI, `@Published`-свойства `ObservableObject` и `AppStorage`.

**Чрезмерная сериализация** — антипаттерн, когда `@MainActor` ставят «на всё» в типе, даже на тяжёлые вычисления, которые к UI отношения не имеют. Это превращает главный поток в узкое горлышко: любая тяжёлая операция внутри `@MainActor`-типа блокирует не только UI, но и все остальные методы этого типа, ведь все они выполняются последовательно на одном и том же акторе.

```swift
@MainActor
func processData() async {
    // ❌ тяжёлые вычисления на главном потоке
    for _ in 0..<1_000_000 {
        _ = UUID().uuidString
    }
}
```

Как избегать:

- **Выносить тяжёлую работу в фон**, а на главный актор возвращаться только за готовым результатом:

```swift
func loadData() async {
    let data = await Task.detached { process() }.value
    await MainActor.run {
        self.result = data
    }
}
```

- **Использовать `@MainActor` точечно**, а не на весь тип целиком:
  - только для свойств и функций, которые обновляют UI или состояние, наблюдаемое `ObservableObject`;
  - остальную логику писать вне `MainActor` и делать hop к нему вручную только там, где это действительно нужно.

Best practices:

- делай UI-связанное строго в `@MainActor`-методах, а не всё подряд;
- обрабатывай данные вне main queue, а возвращай на главный актор только готовый результат;
- не помечай `@MainActor` весь `ViewModel` целиком, если можно выделить в него только UI-часть, а тяжёлую логику держать в отдельном (не изолированном к главному актору) сервисе.

Правильный баланс: `@MainActor` защищает от гонок при обновлении UI и упрощает код, но не должен становиться местом, где выполняется вся бизнес-логика приложения.
