---
title: "Что будет, если несколько сетевых запросов одновременно сохранят результат в одну переменную через главный поток?"
category: concurrency
order: 106
---

Если присваивание всегда выполняется на главном потоке (`DispatchQueue.main.async`), то одновременной записи нет: главная очередь serial, и блоки выполняются по одному. **Data race на самой переменной не возникнет.**

Но остаётся **race condition по логике**:

- ответы приходят в произвольном порядке: медленный ответ на старый запрос может перезаписать более свежий результат;
- «потерянное обновление»: если запросы должны дополнять одно значение, а код читает, меняет и записывает его в разных местах, результат зависит от порядка;
- если присваивание случайно выполняется не на главном потоке (например, в `completion` без переключения), возникает уже настоящий data race.

Как избежать:

- отменять предыдущий запрос при запуске нового (`URLSessionTask.cancel()`, `Task.cancel()`);
- сопоставлять ответ с запросом: хранить идентификатор или токен последнего запроса и игнорировать устаревшие ответы;
- собрать результаты параллельных запросов через `DispatchGroup` или `TaskGroup` и присвоить итог один раз;
- изменять состояние только через одну изоляцию: главную очередь, отдельную serial-очередь или `@MainActor`.

```swift
private var requestID = UUID()

func load() {
    let id = UUID()
    requestID = id                      // запоминаем последний запрос

    service.fetch { [weak self] result in
        DispatchQueue.main.async {
            guard let self, self.requestID == id else { return } // ответ устарел
            self.items = result
        }
    }
}
```
