---
title: "Как устроен полный RenderLoop (цикл отрисовки кадра)?"
category: uikit
order: 141
---

Отрисовка кадра проходит через два процесса.

**В приложении (главный run loop):**

1. **Обработка событий:** касания, таймеры, колбэки; код изменяет view и слои.
2. **Layout:** `updateConstraints`, `layoutSubviews`.
3. **Display:** `draw(_:)` для помеченных view, отрисовка Core Graphics в backing store слоя.
4. **Prepare:** декодирование изображений и преобразование форматов.
5. **Commit:** упаковка изменений слоёв и отправка в render server (в конце итерации run loop, наблюдателем Core Animation).

**В render server (`backboardd`):**

6. **Decode/Draw:** подготовка текстур и выполнение анимаций.
7. **Render:** композитинг слоёв на GPU и вывод кадра на дисплей в момент VSync.

Весь цикл должен укладываться в интервал кадра (около 16,7 мс при 60 Гц, 8,3 мс при 120 Гц). Если любой этап затягивается, кадр пропускается (hitch). Для разгрузки главного потока тяжёлую работу переносят в фон, используют `CATransaction`/`CADisplayLink`, кеширование изображений и избегают offscreen rendering. Отслеживают всё это в Instruments (Core Animation, Time Profiler).
