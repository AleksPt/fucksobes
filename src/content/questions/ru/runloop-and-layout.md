---
title: "Как RunLoop связан с UI layout?"
category: uikit
order: 131
---

Раскладка и отрисовка UI не выполняются мгновенно: они привязаны к главному run loop. Вызовы `setNeedsLayout()`, `setNeedsDisplay()`, а также изменения свойств слоёв только помечают view или слой как изменённые.

Core Animation регистрирует в главном run loop наблюдателя (observer). Когда run loop заканчивает обработку событий и готовится «уснуть» (`beforeWaiting`) или завершает итерацию, наблюдатель запускает цикл обновления: выполняются `updateConstraints`, `layoutSubviews`, `draw(_:)` (для помеченных view) и транзакция отправляется на отрисовку (commit). Поэтому:

- много изменений в одной итерации run loop приводят к одной раскладке, а не к нескольким;
- `layoutIfNeeded()` выполняет раскладку досрочно, не дожидаясь этого момента;
- если главный поток занят долгой работой, run loop не доходит до обновления UI, и интерфейс «замирает».

Режим run loop тоже важен: при прокрутке он переключается в `tracking`, и обработка других источников (таймеров в `default`) приостанавливается.
