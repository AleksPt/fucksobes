---
title: "Какие ограничения есть у протоколов с associated type?"
category: swift
order: 99
---

Протокол с `associatedtype` (или с требованием `Self`) — «универсальный» протокол, поэтому его нельзя использовать как обычный конкретный тип без уточнения:

```swift
protocol Container { associatedtype Item; func get() -> Item }

var c: Container            // до Swift 5.7 — ошибка; сейчас допустимо, но с предупреждением
var c: any Container        // Swift 5.7+ — «экзистенциальный» тип
```

До Swift 5.7 (SE-0309) такой протокол можно было применять только как ограничение дженерика (`func f<C: Container>(c: C)`). Запись без `any` компилятор пока принимает с предупреждением (в будущем языковом режиме это станет ошибкой). Сейчас его можно использовать через `any Container` (с потерей информации об `Item`: значения приходят как `Any` или требуют приведения), а также через `some Container` для непрозрачного возвращаемого типа и параметра. Начиная с Swift 5.7 можно указывать и первичные связанные типы: `any Collection<Int>`.

Другие последствия: нельзя хранить однородный список разных реализаций с разными `Item` без стирания типа (type erasure, например `AnyPublisher`) и сложнее использовать такие протоколы в моках.
