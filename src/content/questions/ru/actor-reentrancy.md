---
title: "Что такое реентерабельность (reentrancy) у акторов и какие проблемы она порождает?"
category: concurrency
order: 111
---

**Reentrancy** (реентерабельность) — свойство актора прерывать выполнение текущего запроса в точке `await`, чтобы обработать другой входящий запрос, а затем вернуться и продолжить исходный. Это не баг, а осознанное решение дизайна Swift Concurrency: без него один зависший `await` внутри актора заблокировал бы вообще все обращения к нему, включая независимые.

Каждый `actor` изолирует своё состояние и обрабатывает запросы по очереди (внутри — как правило, serial-очередь), но именно на точке `await` актор **может** переключиться на обработку другого запроса, не дожидаясь завершения текущего.

```swift
actor BankAccount {
    var balance: Int = 0

    func withdraw(_ amount: Int) async {
        if balance >= amount {
            await notifyExternalSystem() // точка приостановки — актор может уйти к другому запросу
            balance -= amount            // возможно, balance уже изменился другим вызовом!
        }
    }
}
```

Проблема: между проверкой `balance >= amount` и последующим `balance -= amount` другой вызов `withdraw` мог успеть выполниться и изменить `balance` — классический TOCTOU (time-of-check to time-of-use), несмотря на то, что актор в целом защищает от гонок данных на уровне памяти.

Как избегать:

- минимизировать `await` внутри методов актора, особенно между чтением и последующим изменением состояния;
- выносить побочные эффекты (сетевые вызовы, уведомления, UI) за пределы метода актора — актор должен только хранить данные и инкапсулировать бизнес-логику;
- разбивать метод на «чистую» часть без `await` (проверка и изменение состояния одним куском) и «грязную» часть с сайд-эффектами, вызываемую снаружи:

```swift
func withdraw(_ amount: Int) -> Bool {
    guard balance >= amount else { return false }
    balance -= amount   // весь синхронный кусок выполняется без прерываний
    return true
}

// вызывается вне актора
if await account.withdraw(100) {
    await notifyExternalSystem()
}
```

Такой синхронный метод актора (без `await` внутри) выполняется атомарно от начала до конца — реентерабельность просто не успевает вмешаться, потому что нет точки приостановки, на которой актор мог бы переключиться.
