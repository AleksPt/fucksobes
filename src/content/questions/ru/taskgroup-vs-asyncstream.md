---
title: "Чем TaskGroup отличается от AsyncStream/AsyncChannel и когда что использовать?"
category: concurrency
order: 112
---

Оба инструмента про параллельную/асинхронную работу с несколькими значениями, но решают разные задачи: `TaskGroup` — про параллельное выполнение заранее известного набора задач, `AsyncStream` — про поток значений, которые появляются со временем.

**`TaskGroup`** (`withThrowingTaskGroup` и другие варианты) запускает несколько дочерних задач параллельно и структурированно: все они привязаны к родительской задаче, автоматически отменяются, если родитель завершился с ошибкой, и родитель обязательно дожидается их завершения перед выходом из блока.

```swift
func downloadAll(urls: [URL]) async throws -> [Data] {
    try await withThrowingTaskGroup(of: Data.self) { group in
        for url in urls {
            group.addTask { try await download(url) }
        }

        var result: [Data] = []
        for try await data in group { result.append(data) }
        return result
    }
}
```

Подходит, когда **количество задач известно заранее** (например, скачать N файлов) и важна структурированная гарантия отмены и завершения.

**`AsyncStream`** превращает источник значений, поступающих «в разные моменты времени» (таймер, делегат, сокет), в `AsyncSequence`, которую читают циклом `for await`. Подходит, когда **число элементов заранее не известно** — это поток, а не фиксированный набор задач.

**`AsyncChannel`** (из `swift-async-algorithms`) — расширенная версия того же принципа с методами `send`/`receive`, поддерживающая двустороннее взаимодействие между отправителем и получателем, а не только одностороннюю трансляцию значений.

Краткое сравнение:

| | `TaskGroup` | `AsyncStream`/`AsyncChannel` |
|---|---|---|
| Количество задач | заранее известно | динамическое, потоковое |
| Завершение | контролирует родитель | завершает `continuation` вручную |
| Отмена | автоматическая, структурированная | нужно реализовывать явно |
| Подходит для | параллельных вычислений | асинхронных событий (входящие данные) |

Итог: за параллельные вычисления с известным набором задач и контролем отмены/ошибок отвечает `TaskGroup`; за реактивный поток значений, приходящих со временем и в неизвестном количестве, — `AsyncStream`/`AsyncChannel`.
