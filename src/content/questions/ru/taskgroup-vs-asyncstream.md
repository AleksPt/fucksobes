---
title: "Чем TaskGroup отличается от AsyncStream/AsyncChannel и когда что использовать?"
category: concurrency
order: 112
---

Оба инструмента про параллельную/асинхронную работу с несколькими значениями, но решают разные задачи: `TaskGroup` — про параллельное выполнение набора дочерних задач, которые вы сами запускаете и результат которых ждёте, `AsyncStream` — про поток значений, которые появляются со временем из внешнего источника.

**`TaskGroup`** (`withThrowingTaskGroup` и другие варианты) запускает несколько дочерних задач параллельно и структурированно: все они привязаны к родительской задаче, автоматически отменяются, если родитель завершился с ошибкой, и родитель обязательно дожидается их завершения перед выходом из блока.

```swift
func downloadAll(urls: [URL]) async throws -> [Data] {
    try await withThrowingTaskGroup(of: Data.self) { group in
        for url in urls {
            group.addTask { try await download(url) }
        }

        var result: [Data] = []
        for try await data in group { result.append(data) }
        return result
    }
}
```

Задачи добавляются динамически, поэтому их число может быть любым, в том числе неизвестным заранее (например, скачать все файлы из списка). Подходит, когда нужна параллельная работа, которую вы сами запускаете, и структурированная гарантия отмены и завершения.

**`AsyncStream`** превращает источник значений, поступающих «в разные моменты времени» (таймер, делегат, сокет), в `AsyncSequence`, которую читают циклом `for await`. Подходит, когда значения **приходят извне в произвольные моменты** и неизвестно, сколько их будет, — это поток событий, а не набор запущенных вами задач.

**`AsyncChannel`** (из `swift-async-algorithms`) — расширенная версия того же принципа с методами `send`/`receive`, поддерживающая двустороннее взаимодействие между отправителем и получателем, а не только одностороннюю трансляцию значений.

Краткое сравнение:

| | `TaskGroup` | `AsyncStream`/`AsyncChannel` |
|---|---|---|
| Источник значений | дочерние задачи, которые запускаете вы | внешние события, которые приходят сами |
| Завершение | контролирует родитель | завершает `continuation` вручную |
| Отмена | автоматическая, структурированная | нужно реализовывать явно |
| Подходит для | параллельных вычислений | асинхронных событий (входящие данные) |

Итог: за параллельные вычисления из запускаемых вами задач с контролем отмены/ошибок отвечает `TaskGroup`; за реактивный поток значений, приходящих извне со временем, — `AsyncStream`/`AsyncChannel`.
