**Adapter** (адаптер) — структурный паттерн, который преобразует интерфейс одного класса в интерфейс, ожидаемый клиентом, позволяя работать вместе классам с несовместимыми интерфейсами.

Структура:

- **Клиент** — код приложения с существующей бизнес-логикой.
- **Клиентский интерфейс** — протокол, через который клиент ожидает работать с объектами.
- **Сервис** — полезный класс (часто сторонний), у которого интерфейс не совпадает с клиентским.
- **Адаптер** — реализует клиентский интерфейс и хранит ссылку на сервис; принимает вызовы от клиента и переводит их в вызовы, понятные сервису.

```swift
protocol JSONExporting {
    func export() -> Data
}

// Сторонняя библиотека с несовместимым интерфейсом — менять её нельзя
final class LegacyXMLLibrary {
    func generateXML() -> String { "<data>...</data>" }
}

// Адаптер приводит LegacyXMLLibrary к ожидаемому клиентом интерфейсу
final class XMLToJSONAdapter: JSONExporting {
    private let legacy = LegacyXMLLibrary()

    func export() -> Data {
        let xml = legacy.generateXML()
        return convertXMLToJSON(xml)
    }
}

func save(_ exporter: JSONExporting) { /* работает только с JSONExporting */ }
save(XMLToJSONAdapter())
```

Когда применяют:

- нужно использовать сторонний или уже существующий класс, чей интерфейс не подходит остальному коду приложения;
- нужно унифицировать несколько похожих классов под общий интерфейс, но менять их код нельзя (сторонняя библиотека) или нежелательно (пришлось бы дублировать код по подклассам).

Клиент работает с адаптером только через клиентский интерфейс, поэтому не привязывается к конкретной реализации — адаптеры можно менять или добавлять новые независимо от остального кода, например при выходе новой версии сторонней библиотеки.

Плюсы: отделяет и скрывает от клиента детали преобразования интерфейсов.

Минусы: усложняет код добавлением ещё одного класса-прослойки.
