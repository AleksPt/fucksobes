---
title: "Как обеспечить порядок выполнения задач в actor и почему в нём возможны зависания?"
category: concurrency
order: 115
---

Актор — серийный исполнитель (isolated context), обрабатывающий обращения по очереди: все запросы к его изолированным методам идут в очередь актора, но порядок их фактического выполнения не всегда интуитивно очевиден — особенно там, где внутри методов есть `await`, на котором актор может переключиться на обработку другого запроса (см. reentrancy).

Один из характерных сценариев зависания — рекурсивный вызов актора самого себя через `await`, если между вызовом и его завершением нет способа продвинуться вперёд:

```swift
actor Logger {
    func log(_ message: String) async {
        await flush() // точка приостановки
        print(message)
    }

    func flush() async {
        await log("flushing") // рекурсивный вызов → бесконечный цикл
    }
}
```

Здесь `log` ждёт `flush`, а `flush` снова вызывает `log` — задачи ставятся в очередь актора одна за другой, ни одна не завершается, и происходит эффективное зависание (не классический deadlock в терминах блокировки потока, а бесконечно растущая очередь ожидающих друг друга задач).

Как отлаживать:

- использовать `OSSignpost` или `os_log` с временными метками, чтобы увидеть порядок входа и выхода из методов актора;
- логировать вход и выход в каждый метод актора, особенно рядом с `await`, чтобы увидеть, где цепочка вызовов заворачивается сама на себя.

Best practices:

- избегать `await` между чтением и записью состояния внутри актора — короткие синхронные методы без `await` выполняются атомарно, и реентерабельность не успевает вмешаться;
- разделять обязанности: актор хранит данные и инкапсулирует бизнес-логику, а внешний `Service`/`ViewModel` управляет порядком вызовов его методов, а не сам актор рекурсивно вызывает себя.

```swift
actor Bank {
    private var balance = 0

    func withdraw(amount: Int) {
        balance -= amount
    }

    func getBalance() -> Int {
        balance
    }
}
```

Оба метода здесь синхронны (без `await` внутри) — вызов гарантированно выполняется от начала до конца без прерываний, что упрощает рассуждения о порядке и предотвращает реентерабельность.
