---
title: "Сколько сессий (URLSession) может быть в приложении? Какие запросы можно группировать в одну сессию, а какие нельзя?"
category: networking
order: 17
---

Ограничения на число сессий нет, но создавать их на каждый запрос не нужно. Сессия — это **конфигурация и общий контекст**: таймауты, кэш, cookies, заголовки по умолчанию, прокси, пул соединений и делегат. Поэтому запросы с одинаковыми настройками группируют в одну сессию, а разные по настройкам разносят.

В одну сессию можно объединять запросы:

- с одной конфигурацией (таймауты, кэш, cookies, заголовки);
- с общим делегатом (аутентификация, метрики);
- к одному сервису: соединения переиспользуются (HTTP/2, keep-alive), что быстрее.

Отдельная сессия нужна, если требуется:

- **фоновая загрузка**: `URLSessionConfiguration.background(withIdentifier:)`, идентификатор уникален в приложении;
- **`ephemeral`**-режим без кэша и cookies на диске (например, для приватных данных);
- другие **таймауты**, политика кэша или доступ по сети (`allowsCellularAccess`);
- другой **делегат**: например, SSL pinning для конкретного хоста;
- отдельное хранилище cookies или учётные данные.

Практика: одна `URLSession.shared` для простых запросов, одна настроенная сессия на сетевой слой и отдельные — для фона и особых случаев.

Важно: сессия **сильно удерживает своего делегата**, поэтому созданную вручную сессию нужно завершать через `finishTasksAndInvalidate()` (или `invalidateAndCancel()`), иначе возникнет утечка.

```swift
let api = URLSession(configuration: .default)                  // основной сетевой слой
let privateSession = URLSession(configuration: .ephemeral)     // без кэша и cookies
let background = URLSession(
    configuration: .background(withIdentifier: "com.app.upload"),
    delegate: uploadDelegate,
    delegateQueue: nil
)
```
