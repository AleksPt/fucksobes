---
title: "Что делает метод .transition и что должно быть учтено, чтобы он сработал?"
category: swiftui
order: 49
---

`.transition(_:)` описывает, **как именно** view должна появляться и исчезать, когда она вставляется в иерархию или убирается из неё (а не как она выглядит в статике). Сам по себе он не анимирует ничего.

```swift
if isVisible {
    Text("Привет")
        .transition(.opacity.combined(with: .scale))
}
```

Чтобы переход действительно проигрался анимированно, нужно выполнение нескольких условий:

1. **Само появление/исчезновение view** должно быть результатом изменения структуры иерархии — условный `if`/`switch` в `@ViewBuilder`, вставка/удаление элемента из `ForEach`, а не просто изменение свойства уже существующей view (для этого нужен `.animation`, а не `.transition`).
2. Изменение состояния, которое приводит к появлению/исчезновению, должно происходить **внутри `withAnimation`** (или у view должен быть активный `.animation`-модификатор, действующий на этот момент) — без анимационного контекста SwiftUI применит переход мгновенно, без анимации.
3. `.transition` должен быть навешен на саму view, которая появляется/исчезает (или на её родителя, если удаляется целиком контейнер), а не «снаружи» после того, как условие уже сработало.

```swift
withAnimation {
    isVisible.toggle() // без withAnimation переход применится без анимации
}
```

Готовые переходы: `.opacity`, `.scale`, `.slide`, `.move(edge:)`, `.asymmetric(insertion:removal:)` — для разных анимаций появления и исчезновения, а также `.combined(with:)` для совмещения нескольких. Можно написать и полностью кастомный переход через `AnyTransition` и `ViewModifier`.
